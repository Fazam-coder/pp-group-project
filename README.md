# Параллельное сжатие данных: LZ77, Huffman и LZW (C + OpenMP)

Групповой проект по параллельному программированию. Три алгоритма сжатия без потерь реализованы на C в последовательной и параллельной (OpenMP) версиях; параллелизм — по независимым блокам файла размером 1 МиБ. В репозитории есть исследование производительности: ускорение, эффективность, влияние размера задачи и сравнение алгоритмов.

## Структура репозитория

```
huffman/           кодирование Хаффмана (исходник и Makefile)
lz77/              LZ77 с хэш-цепочками (исходник и Makefile)
lzw/               LZW: 12-битные коды, словарь 4096 (исходник и Makefile)
metrics/           результаты измерений производительности
docs/              report.pdf (отчёт) и presentation.pdf (презентация)
.github/workflows/ автоматические проверки GitHub Actions
README.md          этот файл
```

## Сборка

Нужны `gcc` с поддержкой OpenMP и `make`. На macOS используется Homebrew GCC (`gcc-14`/`gcc-15`/`gcc-16`, Makefile выбирает его сам); на Windows — MSYS2/MinGW-w64 или WSL.

Каждый алгоритм собирается из своей папки:

```bash
cd huffman      # или lz77, или lzw
make            # параллельная версия (OpenMP)
make <имя>_seq  # последовательная версия: huffman_seq, lz77_seq или lzw_seq (тот же код без OpenMP)
make clean
```

При сборке `lzw.c` GCC может выдать предупреждение `-Wtype-limits` про сравнение `count > LONG_MAX`; на работу программы оно не влияет.

## Запуск

У всех трёх программ одинаковый интерфейс (команды выполняются в папке алгоритма):

```bash
./huffman c input output [потоки]   # сжать
./huffman d input output [потоки]   # распаковать
./huffman v input [потоки]          # проверить: сжать, распаковать, сравнить с исходным
```

Вместо `huffman` можно указать `lz77` или `lzw`. Если число потоков не указано, используется максимум OpenMP (`OMP_NUM_THREADS`). Последовательные версии (`*_seq`) принимают те же аргументы.

Режим `v` печатает итог и время:

```
input.txt: OK (in=..., compressed=..., compress=... s, decompress=... s, threads=8)
```

Режим `c` у Huffman и LZ77 дополнительно печатает в `stderr` размер входа и выхода и коэффициент сжатия, у LZW — только время. Время во всех режимах — только вычислительная часть, без чтения и записи файлов.

## Как устроено

- Файл читается в память и делится на блоки по 1 МиБ (`BLOCK`).
- Каждый блок сжимается независимо: свой словарь (LZ77, LZW) или своя таблица частот и кодов (Huffman).
- Цикл по блокам распараллелен директивой `#pragma omp parallel for schedule(dynamic) num_threads(threads)`. Поток пишет только в свои `res[b]` и `csize[b]`, поэтому блокировки не нужны; единственная синхронизация — барьер в конце цикла.
- Запись файла последовательная, строго по порядку блоков, поэтому результат не зависит от числа потоков.
- Распаковка: смещения блоков считаются по массиву размеров из заголовка, затем блоки распаковываются параллельно в непересекающиеся области выходного массива.

### Формат сжатого файла

| Алгоритм | Заголовок | Блок |
|---|---|---|
| Huffman | `size_t` размер, `size_t` число блоков, `int csize[]` | `uint32` размер блока, `uint16` K, K пар (символ, длина кода), битовый поток |
| LZ77 | как у Huffman | токены: литерал `0, байт`; повтор `1, расстояние (2 байта), длина−3` |
| LZW | `"LZW1"`, `uint64` размер, `uint32` число блоков, `uint32 size[]` | 12-битные коды, упакованные по битам |

Файлы Huffman и LZ77 используют `size_t` и `int` в порядке байтов и с размерами платформы, поэтому переносить такие файлы между разными архитектурами не стоит; в формате LZW порядок байтов задан явно (little-endian).

## Результаты (кратко)

Windows 11, 4 физических ядра / 8 логических потоков, блок 1 МБ, текст 32 МБ, 3–5 повторов (медиана). Подробности, таблицы и графики — в `docs/report.pdf`.

| Алгоритм | Коэфф. сжатия (текст) | Ускорение сжатия, 8 потоков | Ускорение распаковки, 8 потоков | Случайные данные |
|---|---|---|---|---|
| LZ77 | 0,70 | 3,99× | 5,12× | ×2,00 |
| Huffman | 0,59 | 3,80× | 4,17× | ×1,00 |
| LZW | 0,51 | 4,25× | 4,27× | ×1,42 |

- До 2 потоков ускорение почти идеальное (эффективность 0,94–1,02), после 4 потоков (число физических ядер) рост замедляется.
- Файл в 1 МБ — один блок, поэтому ускорения нет; с ростом числа блоков ускорение растёт.

### Данные измерений

Данные измерений лежат в `metrics/`; `results.csv` — столбцы: `experiment` (`scaling`, `size`, `random`), `algo`, `kind` (`text`/`random`), `size_mb`, `threads`, `reps`, `ratio` (сжатый / исходный размер), `ctime` и `dtime` (время сжатия и распаковки, с). Ускорение считается как `T(1 поток) / T(N потоков)`, эффективность — как ускорение / N. Точка «32 МБ, 1 и 8 потоков» есть в двух сериях; в отчёте для неё взято среднее значение двух медиан.

## Ограничения

- Параллелизм не превышает числа блоков; блоки не используют повторы друг друга.
- В LZ77 нет энтропийного этапа (случайные данные вдвое увеличиваются); в LZW словарь не сбрасывается после заполнения.
- Декодеры LZ77 и Huffman практически не проверяют входные данные на целостность (LZW проверяет).
